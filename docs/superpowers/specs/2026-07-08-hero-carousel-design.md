# Homepage Hero Carousel — Design Spec

**Date:** 2026-07-08
**Branch:** `redesign/hero-carousel` (commit + push on this branch only — NO merge to main, NO deploy until owner approves)
**Reference:** Kama Ayurveda homepage hero (full-width campaign carousel)

## Goal

Replace the homepage hero video (`HeroSection.tsx`) with a 4-slide, Kama Ayurveda-style campaign carousel. Each slide is one seamless banner: a cinematic still-life scene (ingredients + product only — **no hands, no people, no faces**) that dissolves rightward into a flat brand-color field carrying live HTML text (eyebrow, headline, claim, CTA).

Slide images are generated by the owner in Higgsfield using uploaded real product photos as reference (packaging stays pixel-true — same anti-hallucination principle as the video workflow in `docs/higgsfield-video-workflow.md`). Until then, the carousel ships with existing `public/images/products/*-styled.webp` shots as placeholders so it is fully reviewable.

## Decisions made (with owner)

1. **Full takeover** — the whole hero becomes the carousel. Video, watermark, letter-glow headline, and stats strip retire. The "bottle lists a dozen" claim and 1970 heritage live on as Slide 3.
2. **4 slides** — Ubtan, Hair Care Trio, Why Powder manifesto, Jaison Special Combo.
3. **Live HTML text** — never baked into images (crisp, editable, SEO/a11y, no AI typo risk).
4. **Seamless fade composition** — each image's right side dissolves into a flat brand-color field; the CSS panel behind the HTML text uses the same token so any crop seam is invisible.
5. **Objects only** — still-life scenes: raw ingredients, powders, brass/wood props, product packshots. No hands or people anywhere.

## Component architecture

- **New:** `src/components/home/HeroCarousel.tsx` — one `"use client"` component (~150 lines).
  - Typed `slides` const array at top: `{ image, imageAlt, eyebrow, headline, claim, ctaLabel, ctaHref, panelColor, theme: "light" | "dark" }`.
  - Track: CSS `scroll-snap-type: x mandatory` container → native touch swipe, zero JS for gestures.
  - JS responsibilities only: autoplay (advance every 6.5 s via `scrollTo`; paused on hover/focus/pointer-down; disabled under `prefers-reduced-motion`), desktop arrow buttons, dot indicators, current-slide state from a scroll listener (rAF-throttled).
  - A11y: `role="region"` + `aria-roledescription="carousel"` + `aria-label`, dots are buttons with `aria-label="Go to slide N"`, `aria-current` on active dot.
- **Changed:** `src/app/(storefront)/page.tsx` — `HeroSection` → `HeroCarousel`.
- **Changed:** `src/app/layout.tsx` — hero preload `<link>` repointed from `hero-poster.webp` to slide 1's image.
- **Retired (file kept, unused):** `HeroSection.tsx`. Delete in a later cleanup once carousel is approved.

## Layout

- **Desktop:** banner ~`clamp(480px, 62vh, 640px)` tall, full-width. Image `object-cover object-left` fills the slide; text block absolutely positioned over the right ~40% (the flat color field), vertically centered. Arrows at left/right edges, dots bottom-center.
- **Mobile:** vertical stack per slide — image top (scene side, ~4:5 crop via `object-cover object-left`), solid panel-color text block below. Swipe to change slides; dots below.

## Performance guardrails (protect the 220 ms LCP)

- Slide 1 image: `next/image` with `priority` (→ preload + `fetchpriority=high`); it becomes the LCP element, same as today's poster.
- Slides 2–4: default lazy loading.
- No new dependencies; transitions are native scroll (composited). Autoplay timer starts after hydration — first paint is pure server HTML + slide 1 image.
- Removing `hero-group.mp4` (892 KB) from the page is itself a bandwidth win.

## Image spec (Higgsfield)

- **Ratio/size:** 16:9, highest resolution offered (≥ 2048×1152). Desktop displays a ~2.6:1 center crop → keep all subject matter inside the vertical center band and the left 55%.
- **Composition:** subject cluster weighted left; right ~40% dissolves into a seamless flat field of the slide's panel color. No text, no hands, no people, no invented packaging — real packaging comes only from the uploaded product photos.
- **Post-processing:** crop/adjust if needed, export WebP q80 at 2464×1080 (desktop) — `cwebp -q 80`. Target < 220 KB per slide.
- **File paths (fixed contract):** `public/images/hero/slide-1-ubtan.webp`, `slide-2-trio.webp`, `slide-3-manifesto.webp`, `slide-4-combo.webp`. Owner drops generated files in; no code change needed.
- **Placeholders until then:** existing styled shots from `public/images/products/` (e.g. `ubtan-styled.webp`), displayed with the same layout.

### Prompt notes

- Hex codes are kept in-prompt AND described in words — models weight the words; the hex nudges. Expect the field color to land close but not exact: the CSS panel overlaps the fade zone, so small mismatch is hidden by the blend.
- If a generation puts objects in the right third, regenerate — that zone must stay empty for text.
- If packaging warps, re-run with the product photo re-uploaded / higher reference strength rather than accepting a warped jar.

## Revision 2 (July 8, after first Higgsfield render) — baked-text banners

Owner reviewed the live HTML-text version against the first real render and pivoted:

1. **Text is now baked into the artwork** (owner decision, reverses Decision 3). Each slide is a single finished banner image; the whole slide is one `<Link>` to the campaign URL. SEO/a11y preserved via descriptive `alt` + a visually-hidden headline/claim inside the link. Arrows/dots/autoplay stay native HTML.
2. **Two assets per slide (art direction)**: desktop `16:9` banner + mobile `4:5` portrait ("reel-ratio") banner, both with baked typography. Served via `<picture>` + `getImageProps` so only the matching asset downloads. Mobile container: `aspect-[4/5]`; desktop: `h-[clamp(480px,62vh,640px)]`.
3. **File contract:** `public/images/hero/slide-N-<name>.webp` (desktop) + `slide-N-<name>-mobile.webp` (mobile portrait). Slide 1's first portrait render (Higgsfield job `eb5f3567`) is already in as the mobile asset.
4. **Safe-crop band:** desktop displays 16:9 assets at up to ~2.9:1, so prompts must keep all typography + hero objects inside the middle ~60% of frame height. Mobile 4:5 assets display near-uncropped.
5. **Prompt learnings from render 1** (gpt_image_2, aspect "auto" → portrait): set the aspect ratio explicitly in the Higgsfield UI (auto follows the reference photo's shape); prefer Nano Banana Pro for baked typography; backdrop must be prompted "bright, evenly lit, NOT dark chocolate" (render came out too dark); drop chickpea flour; drop the "powder drift in the air" line (rendered as dust specks).
6. The manual `<link rel="preload">` in `layout.tsx` was removed — slide 1 renders as an eager `fetchpriority=high` `<img>` in server HTML, and a raw-file preload would double-fetch beside the optimized `/_next/image` URL.

Prompt pack v1 (above) is superseded for typography-less images; v2 prompts (baked text) are delivered in-session, slide by slide, pending owner approval of slide 1's art direction.
